# 汽水音乐 · 自动领取广告福利（安卓 / AutoJs6）

用 [AutoJs6](https://github.com/SuperMonster003/AutoJs6) 在安卓手机上自动看汽水音乐广告、领取免费听歌时长。
纯手机内运行，不需要电脑，不需要数据线。

> 这是 [qishui-music-welfare-auto](https://github.com/jianqiang1235/qishui-music-welfare-auto)（iOS/AScript 版）的安卓版本。
> iOS 版靠 OCR 猜坐标；安卓有控件树，能直接按文字找到按钮，所以这一版**以控件选择器为主、OCR 只做兜底**，稳定性高一个层级。

---

## 特性

| 能力 | 说明 |
|---|---|
| 控件优先 | 用 `text()/desc()` 直接定位按钮，不依赖分辨率与坐标，换机型不用改代码 |
| 倒计时自适应 | 按界面上显示的剩余秒数续期，基础 40s / 封顶 150s，**31 秒以上的长广告不会误判** |
| 领奖两步确认 | 点了「领取奖励」后必须看到「领取成功」才算成功，没确认就重试一次 |
| 落地页三层兜底 | 「完成」→ 系统返回键/边缘右滑 → 回桌面重启 App |
| 误判防护 | 落地页需要「强特征单条命中」或「弱特征两条以上」，不会把正常广告底部的下载条误判成落地页 |
| 连续无进展重启 | 连续 3 轮没领到就重启 App，避免卡在异常页面空转 |
| 全程落盘日志 | `/sdcard/qishui-autoqishui/run.log`，长跑后可直接看每轮结果 |
| 无设备回归 | 自带 mock 运行时，`node mock/run-mock.js` 可在电脑上验证控制流 |

## 快速开始

```text
1. 手机装 AutoJs6（GitHub Releases 下载 APK）
2. 打开 AutoJs6 → 左侧菜单 → 无障碍服务 → 打开
3. 把整个 qishui-android-autojs 文件夹拷到手机（或从 AutoJs6 里新建项目后粘贴）
4. AutoJs6 里打开 tools/自检.js 跑一遍，确认各项通过
5. 打开 main.js，点运行
```

首次运行会弹「屏幕截图」授权框，**必须点「立即开始」**，否则 OCR 兜底不可用。

详细步骤见 [docs/安装与使用.md](docs/安装与使用.md)。

## 关键参数（config.js）

| 参数 | 默认 | 作用 |
|---|---|---|
| `APP_PACKAGE` | `com.luna.music` | 汽水音乐安卓包名。装错包（比如极速版）要改这里 |
| `MAX_LOOP_COUNT` | `0` | 最多跑几轮，`0` = 不限 |
| `AD_TIMEOUT_BASE` | `40` | 等待广告的基础时长（秒） |
| `AD_TIMEOUT_MAX` | `150` | 等待封顶，无论倒计时显示多少 |
| `IDLE_BEFORE_RESTART` | `3` | 连续几轮没进展就重启 App |
| `IDLE_SLEEP` | `8000` | 空转时每轮间隔（毫秒） |

关键词全部集中在 `config.js` 的数组里（入口按钮、领奖按钮、成功提示、落地页特征……），
界面文案一变，往数组里加一条就行，不用改逻辑。

## 关于包名（重要）

汽水音乐 **iOS 版是 `com.soda.music`，安卓版是 `com.luna.music`**，两者不一样。
脚本默认用 `com.luna.music`。如果你的版本不同：

- 跑 `tools/自检.js`，它会报「汽水音乐已安装」是否通过
- 或者用采集工具看 dump 文件里的「包名」一行
- 拿到正确包名后改 `config.js` 的 `APP_PACKAGE`

## 无设备回归（电脑上跑）

```bash
node mock/run-mock.js
```

三个场景：

| 场景 | 验证什么 | 结果 |
|---|---|---|
| normal | 35 秒广告（故意超过上游固定 30s 超时）能否正常领奖 | PASS，3/3 轮领奖 |
| landing | 广告结束跳电商落地页，能否退出并继续 | PASS，3 次全部退出 |
| noad | 没有倒计时（无广告可看）时能否快速失败 | PASS，不死等 150 秒 |

详见 [mock/测试结果.md](mock/测试结果.md)。

## 必须说明的两件事

**1. 界面文案未经安卓真机验证。**
本项目是在没有安卓设备的环境里写出来的：包名、AutoJs6 API 均已查证文档，控制流用 mock 验证过，
但**具体按钮文案（「免费听歌」「领取奖励」等）是按 iOS 版实测文案 + 安卓常见文案推断的**。
第一次跑很可能出现「找不到按钮」——这不是 bug，是文案没对上。
解决办法：跑 `tools/采集界面.js`，把 dump 里的实际文案补进 `config.js` 对应数组，通常 5 分钟搞定。
详见 [docs/适配说明.md](docs/适配说明.md)。

**2. 这类自动化可能违反应用的用户协议。**
自动看广告领福利属于对平台的机械化操作，账号存在被风控/限制的可能。
本项目仅供学习 AutoJs6 与安卓无障碍自动化的技术实践，请自行评估风险，不要用于商业用途或批量账号操作。
