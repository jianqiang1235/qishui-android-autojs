# 无设备回归结果

环境：Node.js 22，Linux，无安卓设备。
方式：`mock/stub.js` 用假 AutoJs6 运行时 + 虚拟时钟 + 界面状态机替换全部安卓 API，
`sleep()` 只推进虚拟时间（`Date.now()` 也接到虚拟时钟），所以整个回归在毫秒级跑完。

跑法：

```bash
node mock/run-mock.js
```

---

## 结果总览

| 场景 | 验证点 | 领奖次数 | 落地页退出 | 点击次数 | 虚拟耗时 | 结果 |
|---|---|---|---|---|---|---|
| `normal` | 35 秒广告（超过上游固定 30s 超时）能否正常领完 3 轮 | 3 | 0 | 24 | 140s | **PASS** |
| `landing` | 广告结束跳电商落地页，能否退出并进入下一轮 | 0 | 3 | 6 | 155s | **PASS** |
| `noad` | 广告页没有倒计时（无广告可看）时能否快速失败 | 0 | 0 | 24 | 94s | **PASS** |

**3/3 全部通过。**

## 每个场景具体验证了什么

### normal：35 秒广告

这是针对 iOS 版踩过的最大坑设的用例——上游 `wait_ad_countdown(timeout=30)` 写死 30 秒，
31 秒以上的广告必然被误判成"没有广告"，白等一整轮。

本例故意设 35 秒，验证自适应逻辑：

```
[INFO] 倒计时 35s（来源 ui，原文「35秒后可领奖励」）
[INFO] 倒计时 34s ...
...
[STEP] 已点领奖，等待确认
[INFO] 领取成功（控件确认）
[STEP] 第 1 轮领取成功（累计 1 次）
```

三轮回合全部完成，说明：
- 倒计时能被 `textMatches` 正则识别
- 按剩余秒数续期生效（没有在 30 秒时就放弃）
- 领奖 → 成功确认链路完整

### landing：落地页兜底

广告播完后界面变成电商商详页（`向上滑动浏览落地页` + `领券购买` + `完成`），验证三层兜底的第一层：

```
[WARN] 检测到落地页，开始退出
[INFO] 点击「完成」
[INFO] 「完成」退出落地页成功
```

三轮里每轮都成功退出（共 3 次），回到主页后继续进广告，没有卡死。

同时验证了**误判防护**：`landing` 场景下判定需要「向上滑动浏览落地页」这条强特征命中，
而不是靠「立即下载」「商家推荐」这类弱特征——后者在正常广告底部就有，iOS 版曾因此在正片上乱滑。

### noad：无广告快速失败

进广告后界面只有广告区、没有倒计时文本。验证不会死等封顶 150 秒：

```
[WARN] 等待 40s 仍未出现倒计时，判定本轮没有广告
[WARN] 第 1 轮没有广告可看（累计空转 1）
```

40 秒（虚拟）后放弃，而不是耗到 150 秒封顶。三轮共 94 秒虚拟时间。

## 这套回归覆盖不到的地方

必须说清楚，避免误判为"已验证"：

| 已覆盖 | 未覆盖 |
|---|---|
| 控制流：不会死循环、不会无限等待 | 真实按钮文案是否对得上 |
| 倒计时自适应逻辑 | 真实控件树结构（WebView / 自绘控件） |
| 落地页判定与三层兜底分支 | 真实手势与点击是否被系统接管 |
| 领奖两步确认与失败分级 | OCR 实际识别效果（mock 里 OCR 直接返回控件文字） |
| MAX_LOOP_COUNT / 空转重启逻辑 | 真实广告出现的随机性 |

真实界面文案需要通过 `tools/采集界面.js` 现场采集后补进 `config.js`，
这一步只能在有安卓设备的环境里做。
