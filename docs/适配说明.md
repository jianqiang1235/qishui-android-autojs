# 适配说明：换了手机 / 版本更新后怎么改

安卓自动化的界面会随版本变，但**改起来比 iOS 容易得多**——不用猜坐标，只要文案对上就能点到。
本文说明：怎么定位问题、怎么用采集工具、改哪一行。

---

## 一、先判断是哪一类问题

跑一轮后看日志，对照下面三种症状：

| 日志表现 | 说明 | 去改哪里 |
|---|---|---|
| `本轮没能进入广告` | 找不到「免费听歌」这类入口按钮 | `config.js` → `AD_ENTRY_KEYWORDS` |
| `等待 40s 仍未出现倒计时` | 进广告了但认不出倒计时文本 | `config.js` → `COUNTDOWN_PATTERN` |
| `没有找到领奖按钮` | 广告播完但认不出领奖按钮 | `config.js` → `CLAIM_KEYWORDS` |
| `领奖已点击但未看到成功提示` | 点了但认不出成功提示 | `config.js` → `CLAIM_OK_KEYWORDS` |
| `检测到落地页` 反复出现 | 落地页特征命中太宽泛 | `config.js` → `LANDING_KEYWORDS`（删掉容易误判的弱特征） |
| `汽水音乐已安装` 自检失败 | 包名不对 | `config.js` → `APP_PACKAGE` |

---

## 二、用采集工具拿到真实文案（核心步骤）

这是整个适配里最省时间的一步。

### 1. 让界面停在需要适配的画面

比如"进广告失败"，就手动把汽水音乐打开，点一次「免费听歌」之前的那个播放页/弹窗，**停在能看到入口按钮的界面上**。

### 2. 跑采集工具

AutoJs6 里打开 `tools/采集界面.js` → 运行。

### 3. 拿到 dump 文件

路径：`/sdcard/qishui-autoqishui/dump-<时间>.txt`，内容长这样：

```
=== 界面采集 1121-160312 ===
包名: com.luna.music
屏幕: 1080x2400  SDK=34
截图: /sdcard/qishui-autoqishui/shot-1121-160312.png

--- 控件树（文字 / 描述 / 坐标 / 是否可点）---
text="免费听歌" desc="听广告免费畅听30分钟" clickable=true bounds=[270,1850,760,1950]
text="开通会员" desc="" clickable=true bounds=[540,820,900,900]
text="我的" desc="" clickable=true bounds=[900,2250,1080,2380]

--- OCR 结果 ---
"免费听歌"  conf=0.96  [270,1850,760,1950] @515,1900
```

### 4. 把文案补进 config.js

看到真实文案是「听广告免费畅听30分钟」而脚本里只有「免费听歌」时，在 `AD_ENTRY_KEYWORDS` 里加一条：

```js
AD_ENTRY_KEYWORDS: [
    "免费听歌",
    "听广告免费畅听",     // 新增
    ...
],
```

保存，重跑。**一般 5 分钟就能对上**。

## 三、关键词该怎么写（经验规则）

**写短不写长。** 脚本用的是"包含匹配"（`textContains`），所以：

| 写法 | 效果 |
|---|---|
| `"免费听歌"` | 匹配「免费听歌」「免费听歌30分钟」「立即免费听歌」 |
| `"听广告免费畅听30分钟"` | 只匹配完全这个句子，版本一改就失效 ❌ |

**避开歧义词。** 不要写 `"领取"` 这种单词——界面上"领取记录""已领取"都会命中。宁可写 `"领取奖励"`。

**落地页特征要克制。** iOS 版踩过的坑：

> 把「立即下载」「商家推荐」「精彩应用」当落地页特征 → 正常广告底部就有下载条 → 被误判成落地页 → 对着正片乱滑 → 卡死。

所以 `LANDING_KEYWORDS` 里只有「向上滑动浏览落地页」是**强特征**（出现它一定是落地页），
其它都是弱特征，需要**同时命中 2 条**才判定。改的时候不要把弱特征当强特征用。

## 四、包名怎么确认

汽水音乐：

| 平台 | 包名 |
|---|---|
| iOS | `com.soda.music` |
| 安卓 | `com.luna.music` |

如果你装的是极速版/国际版，包名会不同。三种确认方式：

1. 跑 `tools/自检.js`，看「汽水音乐已安装」这项
2. 跑 `tools/采集界面.js`，dump 文件第一行就是「包名」
3. 手机设置 → 应用 → 汽水音乐 → 应用信息里通常能看到包名

拿到后改 `config.js`：

```js
APP_PACKAGE: "com.luna.music",
```

## 五、倒计时认不出来怎么办

默认的正则比较宽松：

```js
COUNTDOWN_PATTERN: "\\d+\\s*(秒|s|S)\\s*后?(可)?(领|领取|获得|获取|跳过)?"
```

能匹配：`30秒后可领奖励`、`15s后领取`、`倒计时 8`（这个匹配不到，因为没"秒"）。

如果 dump 里看到是别的写法，比如：

- `还剩 12 秒` → 正则改成 `"\\d+\\s*秒"` 就够了（只要数字+秒）
- `12` 单独一个数字 → 改成 `"^\\d+$"`，但要小心别的数字控件误命中

**注意**：`parseSeconds()` 会取文本里所有数字的最大值。所以文本里混着别的数字（比如"30秒后可领，已领5次"）时会取 30，这是有意的——宁可多等，不要提前判负。

## 六、屏幕适配问题

**基本不需要适配。** 这套脚本只用两种定位：

1. 控件文字定位（`text()` / `desc()`）——与分辨率无关
2. 控件坐标点击（取控件 bounds 中心）——与分辨率无关

只有手势类的用到比例：

```js
SWIPE_START_X_RATIO: 0.003,   // 从屏幕最左边 0.3% 处开始
SWIPE_END_X_RATIO: 0.75,      // 划到 75% 宽度处
```

这是给"落地页退不出去时从左侧边缘右滑"用的，比例在 1080p / 2K / 折叠屏上都适用。

如果某些手机的侧滑返回阈值不同，把 `SWIPE_START_X_RATIO` 调更小（如 `0.001`），
或者直接在 `lib/app.js` 的 `goBack()` 里改成先 `back()` 反正安卓返回键通常可用。

---

## 七、改完怎么验证

1. `MAX_LOOP_COUNT` 改成 `3`
2. 跑 `main.js`
3. 看日志是否 3 轮都出现「领取成功」
4. 通过后改回 `0` 跑长跑

如果改了关键词还是不行，跑 `tools/采集界面.js` 把 dump 贴出来，对照本文第二节重来一遍。
