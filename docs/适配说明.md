# 适配说明：这条路径是怎么定下来的，改版后改哪里

所有结论都来自荣耀畅玩40（WDY-AN00 / Android 13 / 720×1612 / AutoJs6 6.8.0）真机 dump 与实跑日志。

---

## 一、主路径为什么是「免N天」

最初按 iOS 版思路走「福利 → 福利中心 → 看广告赚金币 → 去完成」。

真机实测发现这条路在 VIP 期间**整条消失**：

| 检查点 | 会员态实测 |
|---|---|
| 底部 tab | 发现 / 听抖音 / 音乐 / **会员** / 我的 |
| 播放页右上角金币图标 | 不存在 |
| 会员充值页 | 只有 7天体验卡 / 连续包年 / 12个月 套餐 |
| 「我的」页 | 没有福利中心入口 |

三处 dump 都拿不到金币/福利节点，也就是说**会员期间 App 里根本没有福利中心**。
而会员是「第一次登录就送」，所以这个限制一开始就命中。

同时发现页（底部 tab「发现」）右上角的「免18天」**一直存在**，点它**直接**进激励视频：

```
com.luna.music/com.ss.android.excitingvideo.ExcitingVideoActivity
```

于是主路径改成：**发现页 → 右上角「免N天」→ 激励视频 → 天数 +1**。
旧福利中心流程保留为 `welfareRound()` 备用，只在找不到「免N天」入口时才走。

## 二、新路径六步，每步都有坑

### 1. 回发现页

- 底部 tab 中心 y≈1532；**y 超过 ~1570 会落进手势区，直接回桌面**
- 会员期第 4 个 tab 会从「福利」变「会员」，所以只能按文字找「发现」，不能按位置

### 2. 认「免N天」

- 它**不是普通按钮**：控件树里只有一个空节点 `[579,63][634,121]`，没有 text/desc（Flutter 自绘）
- 唯一能读它的是 OCR
- OCR 认不出（没装插件 / 没给截图权限）时，退到实测比例坐标 `(0.893, 0.057)` = **643,92**

> `[579,63][634,121]` 的中心是 606,92，但实测点 **643,92** 命中率更高。

### 3. 等广告

- 倒计时在 `content-desc`：`19秒后可领取奖励，关闭，按钮`，`text` 为空
- 读法：先 `descMatches`，再 `textMatches`，最后 OCR

### 4. 领取

- 归零后右上角 desc 变成 `领取成功，关闭，按钮`（bounds `[518,48][688,112]`）
- 这个 desc 本身就是到账信号，点它 = 关广告

### 5. 退出「提前解锁」浮层（**最容易卡死的一步**）

倒计时结束后广告会**自动弹出**：

```
再看4个视频提前得
第20日免费听
[ 领取奖励 ]
  坚持退出
```

| 操作 | 结果 |
|---|---|
| 点右上角 × | 无效（浮层盖着，或只是加载下一条） |
| 按返回键 | **无效**，还在广告里 |
| 点「领取奖励」 | 连播下一条，不是退出 |
| 点「坚持退出」 | **退出，回 App** |

「坚持退出」**没有控件文字**，只能按坐标 `(0.500, 0.624)` = **360,1006**。
`welfare.js` 的 `tapContinueExit()` 用三档 y（0.624 / 0.598 / 0.652）轮着点。

### 6. 面板校验

回 App 弹面板，有**两种形态**，两种都要认：

**A 型（日常，用「天」）**

```
再看4个提前享第20天畅听
恭喜获得第19天免费时长畅听
第19天畅听 已领取
第20天畅听 再看4个提前领
```

- 面板 × 在 `(0.903, 0.623)` = **650,1004**
- 坑：面板**同时**列「第19天 已领取」「第20天 再看4个」，取最大天数会把没领的当成领了
- 所以 `panelClaimed()` 用坐标距离给「已领取」配对最近的「第N天畅听」

**B 型（当天满额，用「日」，无「已领取」）**

```
		恭喜获得
		第30日畅听
		权益截止12月20日24:00
		[提醒我每天来]
		[看2个视频 享今日无损音质]
```

- 控件树里**只有一条 desc**：`第30日畅听`（`text` 全空，其它文字都画在图里）
- × 更靠下：`(0.903, 0.674)` = **650,1086**
- 这形态出现就说明今天这条已经领到了（`panelClaimed()` 直接判 `claimed: true, bonus: true`）

## 三、进度怎么判

**不能**用「屏幕上出现领取成功」判，因为天数越往后一条广告不够：

- 第22天：一条广告 → +1
- 第23天起：浮层直接写「再看3个视频提前得 第24日免费听」，要连看好几条才 +1
- 第30天：封顶（非 VIP 最多 30 天）

唯一可信的进度是面板里的「第N天畅听 **已领取**」那个 N：

```
上一轮已领取 = 22，本轮面板仍 22 → 记「尚未 +1 天」，不判成功
本轮面板显示 23            → 记「+1 天」，判成功
```

这个 N 落盘 `/sdcard/qishui-autoqishui/progress.json`，重启不丢：

```json
{"claimedDay":23,"at":1795255512042}
```

首次运行没有该文件时，第一轮只用来**建立基线**（记日志、不判成功）。

**「没涨」不算失败**：`runFreeRound()` 返回 `progress` 状态，主循环把它当作「正常累积」——
空转计数清零、继续看下一条，不会每 3 轮就无谓重启 App（这是 19:03 那轮暴露的浪费）。

## 四、必须处理的干扰

### 1. 直播间形式广告（**当有效广告，不是干扰**）

激励视频会随机换成直播间（实测命中懂车帝带货直播）：

- Activity：`com.luna.music/com.luna.biz.live.plugin.LunaDefaultLivePlayerActivity` 或 `android.app.Dialog`
- 控件特征：`本场点赞` / `更多直播` / `说点什么` / `小时榜` / `人气榜` / `直播间同价`

**早期判断错了**：以为直播不带奖励就退出换一条。实测证明——**直播间同样计时计奖励**，
看够时长后广告容器里照样出现 `领取成功，关闭，按钮`，点浮层「坚持退出」一样 +1 天
（19:03 那轮就靠一条直播间广告把 25 天推到 26 天）。

现在的处理链条（`watchLiveAd()`）：

1. 等约 `LIVE_WATCH_SEC`（34 秒），期间若出现「悬浮窗播放功能上线啦」就点「暂不使用」
2. 到时间后 `back()` 一次，露出底下的 `ExcitingVideoActivity`
3. 读到 `领取成功` → `done`，接着走和激励视频一样的领奖/面板流程
4. 8 轮都没等到 → 退出记 `noad`

### 1b. 「悬浮窗播放功能上线啦」引导弹窗（**最容易造成死循环**）

直播间退出时会弹出：

```
悬浮窗播放功能上线啦
开启悬浮窗播放功能，退出直播间后也能继续观看精彩直播
[暂不使用]  [立即开启]
Activity: com.bytedance.android.livesdk.floatview.VideoFloatWindowGuideDialog
```

它压在广告容器**最上层**。不点掉它，脚本点直播间的 ×、点浮层、按返回键，**全部打在它身上**，
于是出现「每轮都说命中直播间、每轮都点 × 成功、天数一动不动」的假象（18:25–18:41 那 23 轮就是这么废掉的）。

处理：`isFloatGuide()` 认关键词，`dismissFloatGuide()` 点「暂不使用」= `(0.277, 0.598)` = 199,963。

### 1c. 直播浮层盖住广告容器

直播浮层 `LunaDefaultLivePlayerActivity` 是另一个 Activity，`currentActivity()` 只报最上层，
所以 `inAd()`（判 `ExcitingVideoActivity`）会一直是 false。必须 `back()` 一次才能露出广告容器。

### 2. 荣耀系统管家抢前台（**假启动失败**）

`launchPackage()` 常返回成功但前台是 `com.hihonor.systemmanager/com.hihonor.securitycenter.appads.AppSplashAdvertiseActivity`（管家开屏广告）。
App 其实**已经在后台起来了**，只是被广告压着。

实测额外两点：

- 按一次返回键不会回 App，而是落到 **负一屏**（`com.hihonor.hiboard.Workspace`），要再按才到桌面
- 桌面 `com.hihonor.android.launcher` 不能按返回键（会把桌面退掉）

现在的处理：`clearFrontStealer()` 只针对 `systemmanager` / `hiboard` 循环 back（最多 3 次），
退出后重新 `launchPackage` 一次；桌面启动前也先清一遍；主流程外层再重试 4 轮。

### 3. `AnimatedCommercialSheetDialog` 空壳

点完面板 × 之后，这个营销弹窗的宿主 Activity 会**残留成空壳一直挂在前台**，
虽然看不见，但 `currentActivity()` 报的是它，点击也会被它吃掉。

处理：点「免N天」前，若 Activity 含 `hybrid.dialog` 且没有面板关键词 → `back()` 一次清掉。

### 4. 顶部系统通知横幅挡住入口

实测「交管12123 立即查违章记录」这类横幅会飘在顶部，正好盖住右上角 (643,92)，
点下去直接跳到别的 App，然后脚本白等 40 秒。

处理：`guardJump()` —— 点完入口 1.5 秒后校验 `currentPackage()`，
不在汽水音乐就 back 回 App 并记 `noad`；进广告等待上限也从 40 秒降到 18 秒。

### 5. 免费畅听封顶 30 天

非 VIP 用户免费畅听**最多 30 天**（用户确认）。到顶后：

- 面板变成「恭喜获得 / 第30日畅听 / 提醒我每天来」
- 之后再点「免N天」也拿不到广告 → 连续 noad

处理：`FREE_DAYS_MAX = 30`，`claimedDay >= 30` 时启动即提示「今日已满」并退出。

## 五、OCR 插件（重要但非必需）

AutoJs6 6.7+ 把 OCR 拆成插件。没装时 `ocr.detect()` 直接抛：

```
java.lang.IllegalStateException: 没有可用的 OCR 插件符合请求: ML Kit OCR / Paddle OCR / Rapid OCR
```

处理：启动时 `SC.probeOcr()` 真跑一次，失败即 `ocrBroken=true`，之后 OCR 调用立即返回空并**只告警一次**。
主流程照跑（入口用坐标、进度用面板 desc）。

装上插件（插件中心 → Paddle OCR / ML Kit OCR）后多两项能力：OCR 定位入口、直读右上角天数。

## 六、改版后改哪里

| 现象 | 改哪里 |
|---|---|
| 右上角入口位置变了 | `FREE_ENTRY_RATIO` |
| 入口文案变了 | `FREE_ENTRY_PATTERN` / `FREE_DAYS_PATTERN` |
| 「坚持退出」位置变了 | `CONTINUE_DIALOG_RATIO` 或 `welfare.js` 的 `CONTINUE_TAP_Y` |
| 面板 × 位置变了（A 型） | `PANEL_CLOSE_RATIO` |
| 面板 × 位置变了（B 型「日畅听」） | `PANEL_CLOSE_RATIO_ALT` |
| 面板文案变了 | `PANEL_KEYWORDS` / `PANEL_CLAIMED_KEYWORD` / `PANEL_BONUS_DESC_PATTERN` |
| 广告 Activity 变了 | `AD_ACTIVITY_KEY` |
| 直播间特征变了 | `LIVE_KEYWORDS` / `LIVE_PLAYER_ACTIVITY_KEY` |
| 直播间等多久变了 | `LIVE_WATCH_SEC` |
| 悬浮窗引导弹窗文案/坐标变了 | `FLOAT_GUIDE_KEYWORD` / `FLOAT_GUIDE_DECLINE_RATIO` |
| 免费天数上限变了 | `FREE_DAYS_MAX` |
| 拿不到广告的退避策略要调 | `NOAD_RESTART_COUNT` / `NOAD_RESTART_SLEEP` |
| 进广告等待要调 | `FREE_AD_WAIT` |

改之前先跑 `tools/采集界面.js`，把当前页面的 text/desc 和坐标 dump 出来对照。
