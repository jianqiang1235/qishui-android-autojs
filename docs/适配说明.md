# 适配说明：这条路径是怎么定下来的，改版后改哪里

所有结论都来自荣耀畅玩40（WDY-AN00 / Android 13 / 720×1612 / AutoJs6 6.8.0）真机 dump 与实跑日志。

---

## 一、主路径为什么是「免N天」

最初按 iOS 版思路走「福利 → 福利中心 → 看广告赚金币 → 去完成」。

真机实测发现这条路在 VIP 期间**整条消失**：

| 检查点 | 会员态实测 |
|---|---|
| 底部 tab | 发现 / 听抖音 / 音乐 / **会员** / 我的 |
| 播放页右上角金币图标 | 不存在 |
| 会员充值页 | 只有 7天体验卡 / 连续包年 / 12个月 套餐 |
| 「我的」页 | 没有福利中心入口 |

三处 dump 都拿不到金币/福利节点，也就是说**会员期间 App 里根本没有福利中心**。
而会员是「第一次登录就送」，所以这个限制一开始就命中。

同时发现页（底部 tab「发现」）右上角的「免18天」**一直存在**，点它**直接**进激励视频：

```
com.luna.music/com.ss.android.excitingvideo.ExcitingVideoActivity
```

于是主路径改成：**发现页 → 右上角「免N天」→ 激励视频 → 天数 +1**。
旧福利中心流程保留为 `welfareRound()` 备用，只在找不到「免N天」入口时才走。

## 二、新路径六步，每步都有坑

### 1. 回发现页

- 底部 tab 中心 y≈1532；**y 超过 ~1570 会落进手势区，直接回桌面**
- 会员期第 4 个 tab 会从「福利」变「会员」，所以只能按文字找「发现」，不能按位置

### 2. 认「免N天」

- 它**不是普通按钮**：控件树里只有一个空节点 `[579,63][634,121]`，没有 text/desc（Flutter 自绘）
- 唯一能读它的是 OCR
- OCR 认不出（没装插件 / 没给截图权限）时，退到实测比例坐标 `(0.893, 0.057)` = **643,92**

> `[579,63][634,121]` 的中心是 606,92，但实测点 **643,92** 命中率更高。

### 3. 等广告

- 倒计时在 `content-desc`：`19秒后可领取奖励，关闭，按钮`，`text` 为空
- 读法：先 `descMatches`，再 `textMatches`，最后 OCR

### 4. 领取

- 归零后右上角 desc 变成 `领取成功，关闭，按钮`（bounds `[518,48][688,112]`）
- 这个 desc 本身就是到账信号，点它 = 关广告

### 5. 退出「提前解锁」浮层（**最容易卡死的一步**）

倒计时结束后广告会**自动弹出**：

```
再看4个视频提前得
第20日免费听
[ 领取奖励 ]
  坚持退出
```

| 操作 | 结果 |
|---|---|
| 点右上角 × | 无效（浮层盖着，或只是加载下一条） |
| 按返回键 | **无效**，还在广告里 |
| 点「领取奖励」 | 连播下一条，不是退出 |
| 点「坚持退出」 | **退出，回 App** |

「坚持退出」**没有控件文字**，只能按坐标 `(0.500, 0.624)` = **360,1006**。
`welfare.js` 的 `tapContinueExit()` 用三档 y（0.624 / 0.598 / 0.652）轮着点。

### 6. 面板校验

回 App 弹面板，desc 可读：

```
再看4个提前享第20天畅听
恭喜获得第19天免费时长畅听
第19天畅听 已领取
第20天畅听 再看4个提前领
```

- 面板 × 在 `(0.903, 0.623)` = **650,1004**
- 坑：面板**同时**列「第19天 已领取」「第20天 再看4个」，取最大天数会把没领的当成领了
- 所以 `panelClaimed()` 用坐标距离给「已领取」配对最近的「第N天畅听」

## 三、进度怎么判

**不能**用「屏幕上出现领取成功」判，因为天数越往后一条广告不够：

- 第22天：一条广告 → +1
- 第23天起：浮层直接写「再看3个视频提前得 第24日免费听」，要连看好几条才 +1

唯一可信的进度是面板里的「第N天畅听 **已领取**」那个 N：

```
上一轮已领取 = 22，本轮面板仍 22 → 记「尚未 +1 天」，不判成功
本轮面板显示 23            → 记「+1 天」，判成功
```

这个 N 落盘 `/sdcard/qishui-autoqishui/progress.json`，重启不丢：

```json
{"claimedDay":23,"at":1795255512042}
```

首次运行没有该文件时，第一轮只用来**建立基线**（记日志、不判成功）。

## 四、两个必须处理的干扰

### 1. 直播间形式广告

激励视频会随机换成直播间（实测命中懂车帝带货直播）：

- Activity：`com.luna.music/com.luna.biz.live.plugin.LunaDefaultLivePlayerActivity` 或 `android.app.Dialog`
- 控件特征：`本场点赞` / `更多直播` / `说点什么` / `小时榜`

脚本不参与这种形式（要挂 30 秒、还弹满减券）：`isLivePage()` 命中就点右上角 × 再按返回键退出，本轮记 `noad`。

### 2. 荣耀系统管家抢前台

`launchPackage()` 常返回成功但前台是 `com.hihonor.systemmanager`（自己弹开屏广告）。
`app.js` 兜底：3 次失败后回桌面点图标重启，日志「从桌面启动成功」。

## 五、OCR 插件（重要但非必需）

AutoJs6 6.7+ 把 OCR 拆成插件。没装时 `ocr.detect()` 直接抛：

```
java.lang.IllegalStateException: 没有可用的 OCR 插件符合请求: ML Kit OCR / Paddle OCR / Rapid OCR
```

处理：启动时 `SC.probeOcr()` 真跑一次，失败即 `ocrBroken=true`，之后 OCR 调用立即返回空并**只告警一次**。
主流程照跑（入口用坐标、进度用面板 desc）。

装上插件（插件中心 → Paddle OCR / ML Kit OCR）后多两项能力：OCR 定位入口、直读右上角天数。

## 六、改版后改哪里

| 现象 | 改哪里 |
|---|---|
| 右上角入口位置变了 | `FREE_ENTRY_RATIO` |
| 入口文案变了 | `FREE_ENTRY_PATTERN` / `FREE_DAYS_PATTERN` |
| 「坚持退出」位置变了 | `CONTINUE_DIALOG_RATIO` 或 `welfare.js` 的 `CONTINUE_TAP_Y` |
| 面板 × 位置变了 | `PANEL_CLOSE_RATIO` |
| 面板文案变了 | `PANEL_KEYWORDS` / `PANEL_CLAIMED_KEYWORD` |
| 广告 Activity 变了 | `AD_ACTIVITY_KEY` |
| 直播间特征变了 | `LIVE_KEYWORDS` |

改之前先跑 `tools/采集界面.js`，把当前页面的 text/desc 和坐标 dump 出来对照。
